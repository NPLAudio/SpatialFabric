# ADR 0001: Path Studio architecture

Status: accepted (user approved the plan and the four decisions below).

## Context
Authoring object, listener and camera motion inside three different editors is slow and
inconsistent: axes, units, timing and tools differ. The hub already owns the engine-neutral
contracts: canonical coordinates, OSC v1 with `/ack` and `/state`, and read-only scene
discovery. The OSC Controller proves a standalone app works alongside the engines.

## Decisions
1. **Standalone app in the hub** at `Apps/PathStudio`. It shares fixtures with the
   controller and engines and does not depend on any editor being open.
2. **UI stack: PySide6 (Qt) with Qt Quick 3D or OpenGL** for the viewport and timeline.
   The reference model and sampler stay standard-library Python with no GUI import, so
   they run headless in tests, exporters and CI. Tk is rejected for the editor: no usable
   3D or timeline widgets. The controller keeps Tk.
3. **Live streaming and baked export.** Correction recorded after Phase 2 research: the
   engines currently have no inbound verb that moves an object (8100 is the spatial
   *output* receiver/discovery port; spatial messages are engine output). Live streaming
   therefore needs a new, versioned contract verb plus engine support in all three
   engines. **Baked export needs no contract change and is promoted ahead of live
   streaming.** Exporters (Unity clip/ScriptableObject,
   Godot `Curve3D`/`Animation`, Unreal DataAsset/spline) follow and must reproduce the
   golden samples. Engine round-trip plugins come last.
4. **Scope covers object, listener and camera tracks plus named waypoints.** Orientation
   (yaw/look-at) is a compatible later addition. Position sampling must not change.
5. **Contract first.** `Specs/Path-v1.md`, `Schemas/path-v1.schema.json` and
   `Fixtures/path-v1.json` define behavior. Expected fixture values are hand-computed,
   not generated by the implementation.

## Consequences
- Every engine and exporter can be validated device-free against the same numbers.
- Streamed UDP preview is not deterministic; production uses baked assets.
- Qt adds a large dependency, so packaging (PyInstaller, as for the controller) must
  bundle only needed Qt modules and ship Qt/PySide license notices.
- Live send is explicitly armed, targets a chosen host/port, and never starts audio.

## Next phases
1. Skeleton PySide6 app: open/save documents, validation panel, 2D plan view.
2. Scene discovery client (reuse `Examples/OSCSceneQuery`) and object binding.
3. Timeline, keyframe editing, shape generators, undo/redo.
4. Live link with arm/stop, rate and jitter display, simulator-based tests.
5. Baked exporters per engine, then optional editor round-trip helpers.
